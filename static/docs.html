YwMatrix 产品文档

YwMatrix 是一个远程 Agent 管理平台：把散落在各台机器上的 AI Agent（编码助手、本地大模型客户端、自动化工具……）统一接入一个网页对话入口，随时对话、调度、协作，并把它们当作「产品」来安装、升级和分发。

它解决什么问题

  • 一个入口聊所有 Agent：手机 / 电脑打开网页，就能和任何一台机器上的 Agent 对话，不用 SSH 到那台机器
  • 多 Agent 协作：拉群 @ 多个 Agent 分头干活，管理者 Agent 可以编排调度群成员
  • 产品化分发：Agent 以「品牌 + 产品包」的形式上架，终端一键安装 / 升级，管理端可远程推送更新——像应用商店一样管理你的 Agent 舰队
  • 多用户隔离：每人只能看到自己名下的 Agent 和会话；管理员全局可见

三种使用角色

角色入口做什么
最终用户/（聊天页）选 Agent 对话、拉群、审批工具确认
管理员/admin（管理后台）用户 / 品牌 / 产品包 / 设备密钥 / Agent 审批
终端机器本机管理页 127.0.0.1:9321接入网关、托管 Agent 实例、安装运行产品

架构与核心概念

│  聊天页 /        管理后台 /admin     │
└──────────────┬─────────────────────┘
               │ WebSocket (JWT)
┌──────────────▼─────────────────────┐
│              网关 Gateway           │   品牌/产品目录 · 用户与会话存储(MySQL)
│  会话/消息 · 任务调度 · 产品分发      │   data/products/<品牌>/<版本>/ 安装包仓库
└──────────────┬─────────────────────┘
               │ WebSocket (设备密钥)
┌──────────────▼─────────────────────┐
│  终端 AgentClient（每台机器一个）     │
│  · 托管 Agent 实例(stdio/http/ws)   │   ~/.agent-manage/products/ 本机安装目录
│  · 产品安装/升级/本地运行             │   connector.json 接入凭证与本机覆盖
└──────────────┬─────────────────────┘
        ┌──────┼───────────┐
     Agent1  Agent2      Agent3      （Claude Code / DeepSeek / ywcoder / 自研…）
概念一句话解释
网关服务端中枢：聊天消息、任务、账号、品牌与产品目录都在这
品牌Agent 产品的「身份」：名称、logo、连接方式（stdio / http / ws / web / app）。一个品牌 = 一类产品
产品包品牌对应的可安装产物（tar.gz + manifest.json），传到网关后终端可一键安装
Connector每台终端机器上跑的接入进程（AgentClient），网关通过它管理这台机器上的 Agent 实例
Agent 实例品牌在某台机器上的一个具体运行实例（一个品牌可以多机多实例）
会话与某个 Agent（或群）的一段对话；可绑定工作目录；消息持久化在服务端

快速开始

1. 管理员：准备品牌与终端接入

  1. 登录 /admin → 品牌管理 → 新建品牌（名称、logo、连接方式与启动命令）
  2. 设备密钥 → 生成配对码，发给要接入的机器

2. 终端：安装 AgentClient 并配对

  1. 目标机器解压对应平台的 AgentClient 离线包（或直接 clone 仓库运行）
  2. 浏览器打开本机 http://127.0.0.1:9321，填网关地址 + 配对码 → 接入
  3. 管理员在后台「待接入」里批准
# 源码方式启动（Node ≥ 24）
node src/client.ts --config ~/.agent-manage/connector.json

3. 分配 Agent 实例，开始对话

  1. 后台 Agent 管理 → 注册 Agent（选在线 Connector + 品牌）；或终端在本机页「添加 Agent」
  2. 打开 /，左侧选 Agent，发消息即开聊

聊天页 · 界面总览

左侧三栏：消息（按聊天对象聚合的会话列表）、Agent（联系人卡片）、群组；右侧为对话区与输入区；顶部为当前对象的状态栏。

在线状态

  • 会话列表头像右下角小圆点：绿 = 在线，黄（呼吸）= 忙碌（任务执行中），灰 = 离线
  • 对话标题左侧圆点 + 状态徽章：常显「在线 / 忙碌 / 离线」；群显示「N 个成员 · n 在线」
  • Agent 离线时输入框会提示；上线后自动恢复（终端断网会无限重连，恢复即回）
  • Agent 面板按「在线优先」排序，点名称可看详情（平台、心跳、能力、最近任务）

消息与会话

发送与格式

  • Enter 发送，Shift+Enter 换行（可在设置中改为 ⌘Enter 发送）
  • 支持粘贴 / 拖入图片与文件作为附件；回复支持流式渲染（代码高亮、思考过程折叠、任务产物卡片）
  • 斜杠命令：/model 切模型、/permission 切权限模式等（由 Agent 上报，输入 / 弹补全菜单）

会话管理

  • 一个对象可多会话：列表行点箭头展开；hover 出现置顶 / 重命名 / 删除；顶部可搜索当前会话消息（命中高亮）
  • 工作目录：会话可绑定一个目录（标题栏 📂 徽章），Agent 在该目录下干活；首个任务后锁定，换目录自动开新会话
  • 导出：标题栏下载按钮，把当前会话导出为 Markdown
退出页面不中断：任务归属于会话而不是页面——手机上发出任务后退出，任务照常执行；回来重新打开，流式继续、已完成的记录完整可见（离开期间的结果自动对账补全）。

权限确认卡（工具审批）

Agent 执行敏感操作（运行命令、沙箱提权等）时会弹出确认卡：

  • 允许 / 拒绝：只影响这一步操作；拒绝可附理由
  • 同一轮任务可能连续弹多张确认卡（每个工具调用一张），逐张审批即可
  • 确认不设超时——Agent 会一直等你；着急可点输入区「停止」结束任务
  • 输入型卡片（选择项 / 填表单）按提示填写提交

群组与多 Agent 协作

  • 群组面板 → 新建群组：勾选成员、可设「管理者 Agent」（★ 标记）
  • 群聊发消息需 @成员 或 @全体；离线成员自动跳过（会提示跳过了谁）
  • 管理者编排：@管理者后，它可以自主把子任务派发给群内其他成员，结果汇总回它的回复里；父任务取消会级联取消子任务

移动端（PWA）

  • 手机浏览器打开站点 →「添加到主屏幕」，即可像原生 App 一样全屏使用
  • 任务完成会推系统通知（需授权通知权限）；点通知跳回对应会话
  • 弱网 / 断网自动重连；页面被杀掉任务不中断（见上文）

管理后台 · 总览

/admin 需管理员账号。包含：概览（在线 Agent / 忙碌 / 会话数）、用户管理、Agent 管理、品牌管理（含产品分发）、设备密钥与配对码。普通用户仅有只读品牌目录与自己的密钥管理。

Agent 管理

  • 待接入：新 Connector 配对请求的审批（批准后终端拿到正式凭证）
  • 注册 Agent：给在线 Connector 分配品牌实例（终端本机页也可自助添加）
  • 全量注册表（含离线历史）：实时状态优先；可断开连接 / 移除实例 / 改归属

品牌管理

  • 品牌 = 产品身份：名称、描述、能力标签、logo、连接方式
  • 连接方式五选一：stdio 命令启动 / http / ws 服务地址 / web 产品网页（点「打开」开网址）/ app 独立应用（本机路径）
  • 品牌的启动命令写给「默认机器」，各终端可用本机覆盖指向自己的路径（见产品中心）
  • 不建任何品牌 = 开放模式（Agent 自由注册）；建了第一个品牌即进入治理模式（注册必须挂品牌）

产品分发（安装包仓库）

品牌管理页下半区。把 Agent 产品打成 tar.gz（内含 manifest.json）上传，终端即可在产品中心一键安装。

manifest.json 格式

{
  "format": 1,
  "brand": "deepseek",              // 必须与已有品牌同名（上架强制挂品牌）
  "version": "0.1.1-rc.2",          // semver
  "kind": "stdio",                  // stdio | http | ws | web | app
  "name": "DeepSeek Harness",
  "description": "……",
  "launch_cmd": "node {{install_dir}}/bin.js --config {{install_dir}}/x.yml"
}
  • 编辑 manifest：上传后可在线改（launch_cmd、描述等），服务端版本为准，终端安装时覆盖包内版本；brand / version 是目录身份不可改
  • 推送到终端：一键把某版本广播给所有在线终端——已纳管的自动升级并切换实例；外部安装的原地更新；没装的忽略
  • 服务端自动计算 SHA-256 作为校验锚点，终端下载后强制校验

设备密钥与配对码

  • 配对码（推荐）：一次性、默认 24h 有效；谁生成的码，终端注册的 Agent 就归谁
  • 设备密钥（amk_）：长期凭证，可吊销（吊销立即踢线）
  • 终端在配对页填「网关地址 + 配对码」→ 管理员批准 → 凭证自动写入终端 ~/.agent-manage/connector.json

终端 AgentClient · 本机管理页

每台机器跑一个 AgentClient，本机浏览器打开 http://127.0.0.1:9321（仅本机可访问，无需登录）：

  • 连接状态：网关地址、Connector 名、凭证路径
  • Agent 列表：本机托管实例的运行状态、生效命令（本机覆盖 / 品牌默认）、失败原因与自动重试；可编辑启动命令覆盖、移除

产品中心（终端一键安装）

本机管理页的产品中心是一张统一目录：一行一个品牌，串起「安装 → 接入网关 / 本地起 → 升级」全流程。

操作说明
安装 / 升级到 vX从网关下载产品包（自动 SHA-256 校验），装进本机 ~/.agent-manage/products/<品牌>/<版本>/；同品牌已接入的实例自动切到新版本目录并重启
纳管安装产品当前从外部目录运行时出现：装进产品目录并自动把实例切过来（旧目录保留可回退）
接入网关为装好的产品创建 Agent 实例（进聊天页可对话）
本地起 / 停止本地不接网关直接在本机运行（日志：products/<品牌>/local-run.log）；与网关实例双开会有端口 / 数据锁风险，会先提示
原地更新此路径对「外部安装」直接更新其所在目录：停实例 → 备份(.bak) → 换文件 → 重启；Git 仓库内 / 系统目录会被拒绝
卸载删除本机安装目录（已接入的实例需先移除）
离线安装…从 U 盘等本地文件装 tar.gz 包（与远程同格式）

安装目录与外部安装

  • 安装根目录默认 ~/.agent-manage/products，可在产品中心顶部改为数据盘等位置（内部保持 <品牌>/<版本>/ 结构以支持升级回滚）
  • 不在产品目录里装的（如直接从仓库跑的）会显示「外部安装 · 运行 vX」及探测到的路径——版本来自 Agent 运行时自报，路径来自启动命令；实例停了仍可见、可远程更新

离线部署

  • 源码侧打包：npm run bundle && node scripts/build-offline.mjs，产物在 dist/offline/packages/（服务端 Linux x64 + 三平台 AgentClient，自带 Node 运行时，目标机零依赖）
  • 服务端：解压到 /opt/ywmatrix，建 MySQL 库号，改 systemd 单元两处密码后启动（表结构自动迁移）
  • 终端：U 盘拷贝 AgentClient 包；产品包也可走「离线安装…」从本地文件装
  • 升级 = 停服覆盖 bin/ 与 static/ 重启；建议先 mysqldump

常见问题

手机退出页面，任务会中断吗？记录会丢吗？

不会。任务归属会话而非页面连接：退出后照常执行，结果落库；回来打开会话自动对账，离开期间的输出完整可见。

确认框一直不点会怎样？

Agent 会一直等（审批不设超时，从手机赶回来点也来得及）。不想等了点「停止」。

终端断网 / 网关重启，Agent 会掉吗？

AgentClient 无限自动重连（指数退避，封顶 30 秒一次），恢复后自动重新注册，无需人工干预。

升级产品后旧版本还在吗？

纳管安装保留最近两个历史版本目录（current 指针切换）；外部原地更新会把原目录备份为 <目录>.bak-<时间戳>，出问题改回原名即回滚。

同一个产品能在两台机器上各跑一个实例吗？

可以，这正是「品牌 → 多机多实例」的设计；但同一台机器上「网关实例 + 本地起」同时跑一个产品可能端口 / 数据库锁冲突，界面会提示确认。

权限确认想完全不弹？

把品牌启动命令中的 --permission-mode default 改为 bypassPermissions（如 Claude 系 Agent），重启实例生效。
