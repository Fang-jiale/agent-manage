# YwMatrix 网关与客户端体验改造方案

日期：2026-09-19。状态：首版桌面壳、客户端界面与四类安装包已开始落地；以下为完整路线，不能把全部设计项视为已实现。实际能力、构建方式与待验收项见 [桌面客户端说明](../desktop/README.md)。

## 目标与平台范围

把使用路径缩短为「安装／解压 → 连接组织 → 选择智能体 → 开始使用」。
网关负责跨设备对话、组织管理、终端接入与产品分发；客户端负责本机安装、运行、状态与诊断。

| 平台 | 建议交付 | 使用方式 |
| --- | --- | --- |
| Linux x64 | 自带运行时的 tar.gz + systemd 模板 | 后台 Connector + 本机 Web 管理；保留无桌面部署 |
| Windows 10/11 x64 | 标准版 Setup.exe | 安装向导、桌面入口、托盘、可选登录自启 |
| Windows 7 x64 | 独立兼容版 Setup.exe | 同样的界面与配对流程；独立运行时与更新渠道 |
| 麒麟 Linux ARM64 | 桌面客户端 portable.tar.gz | 解压后双击启动器，可创建应用菜单入口；不依赖安装 Node |
| macOS（如纳入本轮） | arm64 / x64 DMG | 使用同一桌面壳与客户端核心 |

用户已确认 Win7 仅需 64 位，不制作 Win7 x86 包。系统基线暂按 Win7 SP1、银河麒麟桌面 V10 / aarch64 设计，SP1 补丁基线及麒麟具体版本仍需实机确认。ARM64 不等于所有国产处理器，其他指令集需要独立产物。

## 已核对的现状

1. `static/client.html` 把连接信息、Agent 列表、产品中心、添加 Agent 堆在同一页。安装、接入网关、本地启动、命令覆盖等动作并列，普通用户必须理解内部模型。
2. 首次接入的默认地址是 `ws://<本机 hostname>:8080/ws/agent`，通常不会指向真实网关。线上地址曾使用 `https://agentmatrix.top:8443`，不能在新客户端中丢掉自定义端口或假设 443 可用。
3. 重新接入需要用户删除配置文件并重启，不是界面操作。
4. `renderStateCard` 在 configured 未变化时提前返回：顶部圆点更新，但卡片内的连接状态可能保留旧值。
5. 产品目录请求失败会清空目录，界面把「加载失败」表现为「没有产品」。客户端每五秒轮询，安装反馈以按钮文本和 Toast 为主。
6. 产品中心存在「已安装」「本地运行」「网关实例」「外部安装」等不同状态，既有重复启动风险，也缺少清楚的下一步。
7. 网关配对入口藏在「设备密钥」下；审批又在「Agent 管理」内。普通用户的入门流程跨多个功能页。
8. 产品包目前按 `brand/version` 寻址，每个版本只有一个 `package.tar.gz`；没有可执行的 OS、CPU 架构、最低系统版本和客户端版本筛选。支持多平台必须先解决这个模型。
9. `src/client.ts` 约 2400 行，包含 CLI、连接、进程、安装和本机 HTTP UI，不能直接作为独立桌面生命周期组件使用。
10. 现有离线打包目标为 Node 18，Windows 产物是 ZIP + start.bat，暂无 Setup、桌面单实例、托盘及客户端自身更新机制。

## 界面设计

### 网关

普通用户导航：工作台、对话、我的设备、智能体中心。
管理员增加：接入审批、用户与权限、产品发布。把 Connector 显示为「设备」，品牌显示为「智能体产品」；协议名称和设备密钥移到高级信息。

- **工作台**：优先展示待我确认、异常设备、正在执行和最近会话，统计数量作为补充。
- **接入设备**：统一向导，包含系统选择、下载客户端、生成接入信息、等待设备上线。配对码仍按原属主、有效期和审批规则工作。
- **我的设备**：显示设备名、系统、客户端版本、连接状态和本机智能体；点击可定位异常及最近一次成功连接。
- **智能体中心**：列表展示用途、支持系统、可用版本、安装状态。普通用户只看到兼容且有权限的操作。
- **管理端发布**：先选择兼容平台和发布渠道，再上传／校验／小范围发布；展示每台设备的更新结果。网关程序、客户端程序和智能体产品三者版本独立。
- **对话**：保留此前的独立草稿、更多菜单和状态提示；把设备离线、网关失联、待审批、智能体启动失败分开解释。

### 客户端

左侧导航：概览、我的智能体、智能体中心、活动记录、设置。

**首次启动**：

1. 输入组织地址与配对码，或导入管理员提供的接入文件；设备名默认取主机名且可编辑。
2. 检查地址、TLS、网关服务与配对码。用户只填 HTTP(S) 地址，内部统一转换 HTTP/WSS 路径，保留端口及受支持的路径前缀。
3. 展示「连接中／等待管理员批准／被拒绝／码已过期／接入成功」，而不是一个无限转圈按钮。
4. 推荐兼容智能体，完成「安装并启用」，进入概览。

**概览**：顶部展示设备是否可接收任务；中部是运行中的智能体和待处理事项；底部保留最近活动。错误提示带「重试」「检查连接」「查看日志」等可操作入口。

**我的智能体**：一张卡片只给一个主动作。运行中可打开对话，未启动可启动，异常可修复；更新、停用、卸载、命令覆盖放入详情或更多菜单。

**智能体中心**：默认「安装并启用」。需要审批时明确停在等待状态，不能把安装成功等同于已可对话。高级用户可选择仅安装、仅本机运行、导入已有安装。

**活动记录**：安装和更新是持久化作业，显示下载 → 校验 → 解包 → 切换 → 健康检查。离开页面再回来仍能看到结果；失败允许重试或回滚。已有任务运行时，更新排队到空闲窗口。

**设置**：连接组织／更换组织、系统代理／直连／自定义代理、数据目录、登录自启、通知、客户端版本、导出诊断。高级区才展示启动命令和原始配置。

### 桌面行为

- 重复启动聚焦已有窗口，不再争抢 9321 端口或互相踢下线。
- 关闭窗口默认收起到托盘，首次说明「智能体仍在后台运行」；明确提供「退出并停止智能体」。没有托盘支持时保留正常可恢复窗口。
- 默认按当前用户运行，避免为了显示界面要求管理员权限；机器级服务安装是另一个明确选项。
- 子进程由客户端核心管理，UI 崩溃／关闭不等于任务退出。更新和退出时处理进程树及未完成任务。
- 原生目录选择、打开日志目录、通知跳转、复制诊断信息；日志导出默认脱敏。

## 技术方案与兼容性

### 共享核心 + 两种展示入口

```text
网关：账户／设备审批／对话任务／产品与客户端发布
                         ↑ 既有协议
客户端核心：连接、配对、进程管理、安装作业、诊断、配置
             ↑                         ↑
Linux x64：本机 HTTP API + Web UI       桌面壳：受限 IPC + 相同 UI
                                       ├─ Windows 标准版
                                       ├─ Windows 7 兼容版
                                       └─ 麒麟 ARM64 portable
```

优先考虑 Electron + electron-builder：复用已有 HTML/JS 与 Node 客户端，不引入第二份业务实现。Tauri 可作为包体优化候选，但不会自动解决 Win7 的旧 WebView 与麒麟系统 WebKit 依赖。

建议拆分为 `src/client/core`、`transport`、`runtime`、`products`、`local-api` 和独立 `desktop/`；核心提供明确的 start/stop/status 以及状态事件。CLI 与桌面入口自行解析参数，避免依赖 `process.argv[1] === import.meta.url` 的启动判断。

桌面渲染页使用打包的本地资源；主进程／preload 只暴露明确的业务动作，不暴露任意执行命令或任意读写文件。Linux Web 入口保留现有 Host、Origin、Content-Type 校验；desktop 使用 IPC 适配，不通过放宽 HTTP 校验来加载 file:// 页面。核心崩溃可被桌面壳检测和重新拉起。

### Windows 7 是独立兼容工作

- Electron 22 是最后支持 Win7 的主版本，内含 Chromium 108 和 Node 16.17.1；已停止上游支持。它可作为兼容验证候选，不能作为所有系统统一冻结的基础。
- 官方 Node 18 不支持 Win7，但存在社区回移版。2026-09-19 核对到 `Alex313031/node18-win7` 的最新公开 release 为 `v18.20.2`，发布附件日期为 2024-05-21，提供 x64 ZIP 和 MSI。ZIP 已下载、校验并纳入兼容版构建，来源与哈希保存在 `desktop/runtime-lock.json`；尚未在 Win7 实测，也未确认持续的安全修复维护。
- 优先验证路线调整为：Win7 桌面壳使用兼容的 Electron 22，核心通过明确路径启动随包携带的 Win7 回移版 `node.exe` 独立子进程。保留现有 Node 18 打包目标、`fetch` 和 Web Streams 代码，先验证真实兼容性，而不是预先降到 Node 16。外部 Node 不会替换 Electron 自带 Node，也不会让现代 Electron 获得 Win7 支持。
- 使用 ZIP 中的运行时作为安装包私有文件，不要求用户先安装 MSI，不修改系统 Node 或 PATH。固定来源、版本、校验值和许可证信息；初次计算的校验值用于锁定已验收制品，不能单凭它证明发布者身份。桌面壳管理子进程的启动、就绪、日志与退出。
- 如果回移运行时验证不通过，再评估 Electron 自带运行时与网络 API 适配路线。降低 esbuild target 只解决语法，不会补齐 API。
- Win7 专项验收包括 `os.hostname()`、HTTPS 证书链、WebSocket 重连、HTTP/SSE 流、子进程启动与终止、中文路径、产品下载解包和文件替换；不能用 `node -v` 成功替代这些检查。
- UI 需要 Chromium 108 基线的 CSS 降级，尤其现有 `color-mix()`；不能出现旧系统启动后文本或背景消失。
- Win7 版只加载固定的本地客户端界面；链接转交外部浏览器，独立兼容更新渠道，禁止自动升级到标准版。
- 「客户端能启动」和「某个智能体能在本机运行」是两项承诺。依赖更高 Node 或系统版本的智能体应在目录中标明不兼容，可引导使用其他设备上的智能体，不能安装到一半才报 DLL 错误。

### Windows Setup

提供标准版与 Win7 兼容版两个全量离线安装包，默认当前用户安装。安装器处理快捷方式、旧版本升级和卸载入口；首次启动配对，不把短期配对码固化进安装程序。卸载默认保留用户配置与数据，并提供明确的清除选项。

同一个 Setup 自动选择两套运行时可作为后续选择，但包体会包含两套内容；第一版优先让下载页推荐正确渠道，保留手动切换。最终需验证签名、中文路径、非管理员安装及重启后的启动行为。

### 麒麟 ARM64 portable

交付 tar.gz，内含完整桌面运行时、核心、界面、启动器和可选 .desktop 入口。解压目录可移动；默认配置与日志仍放用户目录，覆盖应用文件升级不覆盖数据。只有明确选择携带数据模式时才把配置放进便携目录。

应以目标麒麟镜像验证 glibc、libstdc++、GTK/NSS、X11/Wayland、沙箱及托盘支持，不能将「ARM64 包构建成功」视作「麒麟可用」。不默认关闭 Chromium sandbox；缺失系统依赖时明确诊断，必要时提供匹配系统版本的离线依赖包。主交付使用 tar.gz，不要求用户处理 AppImage/FUSE。

### 产品与客户端分发模型

产品包至少增加：`os`、`arch`、`min_os_version`、`runtime_requirements`、`min_client_version`、`channel`、`artifact_id`。
存储／索引改为 `brand/version/artifact_id` 或等价制品表；同一产品版本可挂多平台制品，下载前按当前设备筛选，安装前再次校验。旧无平台字段的包不能直接假定通用：管理员明确标记为纯脚本通用或补录目标平台。

客户端安装包应有独立下载目录、版本及渠道元数据，避免和智能体产品混在同一个升级按钮中。下载页保留所有平台的手动选择，并显示大小、校验值和系统要求。

## 优先级与实施顺序

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0：兼容性验证 | Win7 最小桌面壳 + 核心连接；麒麟 ARM64 最小桌面壳 | 两种真实系统上能启动、连接 TLS/WebSocket、拉起示例智能体并退出 |
| 1：共同体验基础 | 客户端导航、接入向导、状态机、错误解释、诊断；网关统一设备接入 | 从全新设备到首次任务无需编辑脚本或配置文件 |
| 2：核心与桌面壳 | 生命周期拆分、IPC/Web 双入口、单实例、托盘、目录与通知 | 关闭 UI 后任务持续；退出可控；无重复进程；Linux x64 Web 继续可用 |
| 3：分发与更新 | 平台制品模型、作业进度、兼容筛选、Setup/portable、更新回滚 | 错包安装前被拦截；失败恢复旧版；升级保留配置 |
| 4：整体验收 | 各系统安装／重启／离线／更新／卸载与权限测试 | 满足下列验收矩阵后才发布正式安装包 |

不预估一个精确工期：Win7 运行时和具体麒麟镜像的验证结果会决定工作量。可以并行推进设计与代码，但兼容版不能在没有实机验收的情况下标为可交付。

## 验收矩阵

- 平台：Win10/11 x64、Win7 SP1 x64、指定版本的麒麟 ARM64、Linux x64 无桌面。
- 接入：自定义 HTTPS 端口、代理、断网、无效／过期配对码、等待批准、被拒绝、更换组织。
- 安装：全新非管理员用户、中文与空格路径、无系统 Node、离线、磁盘不足、错误架构。
- 运行：stdio/http/ws 各一个示例智能体；完成、失败、取消、待用户确认；重连与进程退出。
- 桌面：单实例、收起／恢复、退出、登录自启、托盘不可用、核心意外退出。
- 更新：忙碌时延迟、下载中断、校验失败、启动失败回滚；portable 移动目录后配置仍可用。
- 网关：按用户隔离不变；显示客户端版本、待审批与异常；发布状态可追踪到设备。
- 性能：记录冷启动、空闲内存与 CPU、五秒轮询替换前后负载，再决定是否继续优化包体或引入其他壳。
